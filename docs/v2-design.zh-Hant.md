# v2 設計：從「話術生成器」到「互動模型」

狀態：已實作，放在分支 `v2-distilled`；`main` 仍是 v1，未合併。

## 1. 為甚麼要改

v1 是一份判斷清單：先判斷關係，再按四段輸出給一句話加備選。它在「幫我把這句話講得得體啲」這個任務上是稱職的。

但它處理不了互動，因為它假設：

- 只有一個回合（你回一句，事情結束）
- 對方會接受你給的台階
- 你要做的只是回應，不需要開場
- 同一句話第一次講和第三次講，效果一樣

真實社交在這四點上都相反。所以 v1 的問題不是不夠長，也不是不夠禮貌，而是**沒有一個對手模型**。

## 2. 蒸餾的定義

這裡的蒸餾指：把枚舉式的規則（七個場景、五條原則、四段格式）壓成少量**生成變量**，令模型可以應付沒寫進清單的情況。

不是：壓字數、換細模型、fine-tune。

驗收標準因此不是「字數少了多少」，而是「未見過的場景，生成得出合理動作」。

## 3. v1 的三個缺口

### 3.1 沒有第二手

全部場景都是「你點回」，沒有一句處理「對方不接受」。而互動最難的正是第二句：

- 「你咩意思？」
- 「大家都係咁做」
- 「呢點忙都唔幫？」
- 「我以為我哋關係唔同」

v1 遇到這些只能重新生成一次婉拒，力度一樣，於是變成原地打轉。

### 3.2 沒有模式級判斷

同一個同事第三次叫你頂更，v1 仍然出「你開口我肯定想幫，但這次確實接不住」。

這句第一次講叫得體，第三次講叫邀請對方再問第四次。互動模型要分得開「斷一次」和「斷一個模式」：前者靠措辭，後者要改規則或者提高成本。

### 3.3 只教 respond，沒教 initiate

一半社交是你主動：幾時開口、用邊個渠道、要唔要先鋪一句、事後補唔補。v1 完全沒有這一層。

## 4. 一個場景走兩版

場景：同組同事第三次叫你頂夜更，前兩次你幫過，今次你有事。

**v1 會出：**

> 你開口我肯定想幫，但這次確實接不住；勉強答應，後面做不到反而更耽誤你。

單句看無問題。問題是它沒有處理「第三次」這個信息，也沒有給你下一句。

**v2 會出（香港書面 register）：**

> 判斷：對等同事、他求你、第三次、私下文字、之後仍要合作。今次目標不是「拒絕得靚」，而是把呢件事由「每次問你」變成「以後唔預你」。
>
> 可以直接用：
> 「阿 Ken，今次我真係接唔到。之前兩次係咁啱我鬆啲，我唔想做成慣例 — 以後排更嘅事你直接同阿頭講，唔好預我。」
>
> 對方最可能嘅兩個反應：
> 1. 「吓，之前又得？」→「之前得係因為情況唔同，我唔想每次都解釋一次。你當我以後都唔得就得。」
> 2. 「咁你早講啦。」→「係我之前講得唔夠清楚，而家講清楚。」（認自己表達不足，不認對方有理）
>
> 渠道與時機：私下文字，今日內，不要等他問第三次。
> 留痕：不需要書面，但要記住自己講過；下次他再問，直接引用「我上次講過」。

同一個場景，大陸 register（此處以繁體呈現，實際使用時寫簡體）：

> 「王哥，這次我真接不了。前兩次是趕上我這邊空，不能養成慣例，以後排班的事你直接找主管吧。」

差別不在語氣，在**動作**：v2 換的是關係均衡，不是句子。

## 5. v2 生成核：五個變量

任何場景，先填這五格，再選動作。

| 變量 | 取值 | 它決定甚麼 |
|---|---|---|
| **P 權力差** | 對方可以影響你的資源／評價 / 對等 / 你影響他 | 你能唔能夠「win the argument」 |
| **D 依賴方向** | 你求他 / 互需 / 他求你 | 你手上有幾多議價空間 |
| **A 觀眾** | 公開（群組、會議、飯桌）/ 私下 / 有中間人 | 面子成本，以及是否需要轉渠道 |
| **R 可逆性** | 一次性 / 會被記住 / 有制度後果（合約、檔案、錢） | 要唔要書面、要唔要留證 |
| **N 未來互動** | 一次 / 偶爾 / 長期 | 讓步讓到幾多、邊界講到幾硬 |

### 動作對應（初版規則）

| 條件 | 動作 |
|---|---|
| P 高 + A 公開 + 對方剛發難 | 不當場爭對錯。接住、把討論移到私下，即使你佔理 |
| P 高 + 你求他 + N 長期 | 不可以贏一次輸關係。讓步要讓得可見，但成本要講清（書面） |
| P 對等 + R 有制度後果 + 你佔理 | 語氣軟、事實硬，公開對齊＋書面留痕 |
| 他求你 + N 長期 + 已拒絕 ≥ 2 次 | 由「拒絕一次」升到「定規則」或「提高成本」 |
| 他求你 + A 有觀眾 | 不當眾拒絕。給「我睇下時間」再私下講 |
| 任何 + 觸及紅線 | 不談判。留證、體面退出、必要時升級 |

「提高成本」是 v1 完全沒有的動作：不拒絕，但把條件開到對方自己不想用。例如「可以，不過要排到下個月，你 OK 就發我。」

## 6. 第二手庫（六類）

| 對方動作 | 骨架 | 例句（香港書面） |
|---|---|---|
| 否認意圖（「我唔係咁嘅意思」「你諗多咗」） | 不爭意圖，回到行為與事實 | 「可能我講得唔清楚。我意思係：X 我可以做，Y 我做唔到。」 |
| 施壓（「大家都係咁」「上次都得」） | 拉回具體條件，不做道德辯論 | 「上次得係因為 A，今次係 B，情況唔同。」 |
| 情緒（「你咁講我好傷心」「唔使咁絕」） | 認情緒，不認結論 | 「我明白你唔舒服，但呢件事我嘅答案仲係一樣。」 |
| 找中間人 | 主動接觸中間人，不等傳話 | 「我直接同佢講清楚，唔想你有手尾。」 |
| 公開將軍（群組 @ 你） | 公開接、私下講 | 「收到，我私下同你對一對細節。」 |
| 事後翻舊帳 | 用記錄，不用記憶 | 「我搵返嗰日嘅訊息對一對先。」 |

六類之外的處理原則：**對方升級，你降溫；對方降溫，你收口。** 不要同時升級。

## 7. register 開關

字形轉換不等於語用轉換。繁體版現在仍然是「領導／介紹人／飯局 AA」的大陸邏輯。

| 維度 | 香港 | 大陸 |
|---|---|---|
| 稱呼 | 陳生、Miss Lee、阿姐、英文名 | X 總、X 老師、哥／姐、您 |
| 回執禮儀 | 群組少用「收到」儀式，WhatsApp 已讀不回可接受 | 「收到請回復」是常態，不回等於態度問題 |
| 金錢 | AA 默認，講明就係講明 | AA／輪請／地主之誼三套並存，要事先對規則 |
| 拒絕語法 | 可以直說「做唔到」，重點是給原因和替代 | 先謝／先接住，原因歸自己，少評價對方 |
| 渠道 | WhatsApp 文字、語音、當面 | 微信、電話、飯局 |
| 權力表達 | 較少敬語，靠職級和程序 | 稱呼與座次本身就是信息 |

實作：skill 頂部一行 `register: hk（預設）| cn`，只影響稱呼、回執、金錢、拒絕語法四處，不動判斷核。

## 8. 輸出契約 v2

1. **判斷** — 一句：關係、風險、你想達成甚麼（是拒絕，還是改規則）
2. **可以直接用的一句**
3. **第二手** — 對方最可能兩個反應，各配一句回應
4. **渠道與時機** — 文字／語音／當面；幾時；要唔要等
5. **邊界與留痕** — 需不需要書面，要留甚麼
6. **解釋** — 最多三句

比 v1 多了 3、4、5。這三項就是「互動」被漏掉的部分。

## 9. Eval 設計

八條對抗案例，全部多輪或高壓：

1. 第三次被同一同事要求頂更
2. 群組被公開 @ 追一筆你沒欠的數
3. 長輩用親情施壓借錢
4. 上司公開否定你的方案，事後證明你對了
5. 朋友託你辦合規邊緣的事
6. 你婉拒後對方冷戰
7. 中間人傳話失真，兩邊都覺得你不給面子
8. 你已經講錯了一句，要補救

評分（每項 0–3）：面子保存、邊界清晰、可執行、後續風險。

比較方法：同一 prompt 分別跑 v1／v2，輸出匿名後由另一個模型或人配對評分，記錄勝負。合併門檻：v2 在八條中勝出 ≥ 6 條，且無任何一條低於 v1 兩個維度。

## 10. 蒸餾會失去甚麼

- **句子多樣性**：v1 的枚舉其實是語料庫，壓縮之後輸出會趨同。補救：把 v1 的例句保留成 `examples/`，核心只引用，不重複。
- **文化細節**：五個變量解釋不了「為甚麼這句在他家鄉不能講」。補救：細節留在 register 附錄，不進核心。
- **可解釋性**：規則變成函數之後，用戶較難自己改。補救：文檔保留「條件 → 動作」表，讓人可以改表而不是改散文。
