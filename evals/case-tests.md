# 人情世故.skill 首轮案例测试

说明：以下测试基于真实网页场景，由我用 `人情世故.skill` 的规则手工跑了一轮，重点看它是否比“直给”“消失”“翻旧账”更符合中国语境。

## Test 1：深夜群通知

### 来源

- 澎湃新闻，2024-12-04
- https://m.thepaper.cn/newsDetail_forward_29547749

### 用户目标

不想夜里展开工作，但也不想第二天被说“态度有问题”。

### 生硬回复

`知道了。`

问题：

- 语气敷衍
- 不够正式
- 不能体现“已接收并会跟进”

### Skill 输出

`收到，明早我再同步一下自己这边安排。`

### 为什么更好

- 满足领导最需要的“回执”
- 不把夜里对话继续拉长
- 给用户争取到白天处理的缓冲

## Test 2：拒绝熟人相亲

### 来源

- V2EX《怎么应对相亲》
- https://fast.v2ex.com/t/163738

### 用户目标

不想继续，但不想让介绍长辈觉得丢脸或白忙。

### 生硬回复

`不合适，别再介绍了。`

问题：

- 否定感太强
- 直接切断介绍人的善意
- 没有给第三方留面子

### Skill 输出

`这次真的辛苦您费心了，对方挺好的，也很真诚。主要还是我自己现在状态和节奏不太适合往下推进，怕耽误人家，所以想先到这里。也麻烦您替我带个谢意。`

### 为什么更好

- 先感谢介绍人
- 不点评对方
- 原因落在自己身上
- 让介绍人有台阶可下

## Test 3：会上反对领导

### 来源

- V2EX《领导专门拉了个会批斗了我一番。大伙帮忙看下，我的设计思路很离谱么》
- https://v2ex.com/t/902902

### 用户目标

表达专业异议，但不要当众把领导顶住。

### 生硬回复

`这个方案不行，风险太大。`

问题：

- 公开否定
- 直接制造立场冲突
- 没有备选方案

### Skill 输出

`我理解您是想先把节奏抢出来，这个方向我认同。我这边补充一个执行风险：如果按现在这个方案直接上，联调和回滚预案会比较被动。要不我准备一个保节奏、但风险更低的版本，您拍板？`

### 为什么更好

- 先对齐目标，避免“对着干”
- 把矛头从“人”转到“风险”
- 最后把决策权留给上级

## Test 4：AA 还是轮请

### 来源

- V2EX《北方同事之间吃饭是 AA 还是轮请制》
- https://v2ex.com/t/1151528

### 用户目标

把钱说清楚，但不显得小气或翻旧账。

### 生硬回复

`前几顿饭钱你们怎么还没转我？`

问题：

- 指责感强
- 容易让对方本能防御
- 没有承认“规则可能没先说清”

### Skill 输出

`这几顿我先垫了，怕大家后面忘记，我把账单一起发群里，咱们顺手对一下就行。要是大家习惯轮请也没事，提前说一声我下次就按这个规则来。`

### 为什么更好

- 不像追债
- 给了“规则理解差异”这个缓冲层
- 借机把以后规则说清

## Test 5：专注时如何不失联

### 来源

- V2EX《专注做事时不回复任何外部请求是情商低吗？》
- https://www.v2ex.com/t/579358

### 用户目标

不被频繁打断，但也不让协作断掉。

### 生硬回复

`我在忙，别烦。`

问题：

- 伤关系
- 容易被贴上难合作标签
- 没有给后续时间预期

### Skill 输出

`我这会儿在收尾一个东西，大概 30 分钟后回你。如果特别急，你先把问题和截止时间发我，我优先看。`

### 为什么更好

- 先回应，不消失
- 给明确时间点
- 保留紧急事项通道

## 总结

首轮测试看下来，这个 skill 的有效点不在“更会说漂亮话”，而在于它稳定遵循了三个动作：

1. 先接住关系
2. 再表明边界
3. 最后给台阶或替代路径

这正是中国语境里很多“高情商”表达真正有效的地方。
